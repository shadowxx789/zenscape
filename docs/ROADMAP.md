## 2. 设计纲领：第一性原理

### 2.1 解构 Endel 的三条公理

1. **声景 = 实时输入函数**，不是预录素材
2. **每个声景对应一个明确的功能态**，有科学锚点（Flow / Circadian / 副交感）
3. **「无重复」来自参数流的连续变化**，不是更长的循环

### 2.2 禅声三公理（区别于 Endel 的"功能主义"）

1. **声音必须服务于"不注意声音"**。越被注意越是失败
2. **留白是材料，不是 bug**。30-90 秒近乎静默是设计的一部分
3. **声音是无常的隐喻**。每个事件有「升起 → 安住 → 消散」三相，不可被预期

### 2.3 ZenScape 真正的护城河

> **Endel 帮你完成任务，禅音帮你忘掉任务。**
>
> Endel 说 "Focus boost 7×" —— 西方功用主义
> ZenScape 应该说 "声声不住，念念不停" —— 东方无功用主义

UX 上**刻意反对目标导向**：
- 不要 streak
- 不要 minutes this week
- 不要 achievement
- 只有"本次会话已圆满"+ 一句偈

## 4. Sprint 1：让声音对得起耳机

### 目标

把现有 5 层声音重做，达到「戴索尼 1000XM5 听 30 分钟不出戏」的工程标准。

### 包含 4 个 Task

| ID | 内容 | 影响 |
|---|---|---|
| A | 粉红噪声替换（Voss-McCartney） | 风/水更像自然声 |
| B | 寺钟非谐分音 | 钟真的像钟 |
| C | Karplus-Strong 古琴 | 拨弦真实感 |
| D | 卷积混响总线 | 整体在山谷里 |

### 不含

- 任何新模式
- 任何新输入
- 任何 UI 改动

### 详细规格

→ 见 `docs/SPRINT_1_SPEC.md`

### 完成验证

戴耳机闭眼听 7 个问题：
1. 像不像在山里？
2. 像不像远处寺钟？
3. 像不像有人在远处拨了一下弦？
4. sleep 模式是不是更暗更远？
5. focus 模式是不是更近更清醒？
6. 30 分钟无 dropout？
7. CPU < 8%？

≥ 6 个是 → Sprint 1 通过。

## 5. Sprint 2：Endel 化响应式输入

### 目标

把 ZenScape 从「按 mode + progress 算参数」升级到「按多维上下文实时回应」。

### 输入源矩阵

| 输入 | API | 默认 | 影响 |
|---|---|---|---|
| 时辰（12 时辰） | `Date` | 开 | drone 基频、bell 概率 |
| 节气（24 节气） | JS 计算 | 开 | 调式、色调、特殊层（虫鸣/雪） |
| 天气 | OpenWeather | 用户授权 | 雨声层、风声层、明亮度 |
| 设备运动 | DeviceMotion | 用户授权 | stillness → 深度 |
| 麦克风环境 | getUserMedia | 用户授权 | 自动 masking |
| 页面可见性 | Page Visibility | 开 | 黑屏加速进入 deep |

### 关键设计

- 所有传感器**默认关闭**，符合禅意"不打扰"
- 麦克风权限申请前明确：**不会录音，只测量噪声等级**
- 全部本地计算，不上传任何数据
- 用户不开任何权限，原行为完全不变（向后兼容）

### 文件交付

- `app/src/audio/inputs/TimeContext.ts`
- `app/src/audio/inputs/WeatherContext.ts`
- `app/src/audio/inputs/MotionContext.ts`
- `app/src/audio/inputs/EnvironmentContext.ts`
- `app/src/audio/inputs/ContextAggregator.ts`
- `rules.ts` 接收新参数

### 完成验证

- 不开权限：原行为完全相同
- 开天气：雨天能听到雨声层
- 开 motion：手机放下 30 秒后声景"安顿"

## 6. Sprint 3：禅式扩展

### 新增模式

| 模式 | 灵感 | 声学锚点 |
|---|---|---|
| 行禅 | 边走边修 | 60-80 BPM 步态同步 + motion 触发 |
| 茶时 | 一期一会 | 蒸汽 + 沸水 + 紫砂倒水 + 极疏古琴 |
| 观息 | 安那般那念 | 4-7-8 呼吸引导 + 极简层 |
| 诵经 | 心经持念 | 男声 vocoder 共鸣 + 木鱼极慢节拍 |

### 新增声音层

1. **木鱼 / 磬** — 呼吸引导节拍
2. **泉水滴落** — Karplus + 随机 pitch，极稀疏
3. **风铃** — 金属泛音束 + 风速触发
4. **远诵** — 极远男声共振（48-60Hz 基频）
5. **蝉鸣**（仅夏至前后自动出现）— FM 合成 + 远场
6. **雪落**（仅冬至前后）— 极高频粒子噪声

## 7. Sprint 4：生成叙事剧本

把现有的 `entering / settling / deep / returning` 升级成更具禅诗意的剧本：

```
入山 (0-5%)
  ↓
见雾 (5-15%)         滤波器扫频缓慢扫描
  ↓
听涧 (15-35%)        水声层增强
  ↓
安住 (35-70%)        最大留白，可能 60-90 秒近乎静默
  ↓
闻钟 (70-85%)        保证至少响一次钟
  ↓
归途 (85-100%)       明亮度缓升
```

每个阶段不是参数百分比，而是**事件概率矩阵**。

## 8. Sprint 5：个性化学习

### 听感校准

首次使用 3 分钟 onboarding：用户给 3 段不同样本打分。

### 偏好 Bandit

- 记录每次会话的完成情况、跳过点、滑杆调整
- 用 ε-greedy 在用户偏好的参数邻域内探索
- 本地存储（localStorage），不上传后端

### 不做的事

- 不上传任何数据
- 不要求账号
- 不要 streak / achievement

## 10. 决策原则备忘

每当面临设计选择时，回到这些原则：

1. **服务于"不注意声音"** > 服务于"提供好听的声音"
2. **留白是材料** > 留白是 bug
3. **响应式 > 预录式**
4. **科学锚点 + 禅意美学** > 只有美学
5. **本地计算 > 上传后端**
6. **不打扰 > 提示用户开权限**
7. **可回滚 > 一步到位**
8. **听感 > 代码优雅**
